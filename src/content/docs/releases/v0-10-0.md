Toft is where an organization's own software lives: web apps, APIs, dashboards,
reports and scheduled work, built in-house by a person or by an agent. A
developer pastes a GitHub repository URL, or pushes the working tree from their
laptop, and Toft builds it, deploys it and serves it at its own address, behind
the organization's own sign-in.

## What it does

- **Deploys from Git or from a laptop.** It detects Next.js, Node, Go, Flask,
  FastAPI, Streamlit, Shiny, Plumber, Quarto, Python, R and static sites from
  the repository, builds them, and keeps every release so a rollback is one
  click.
- **Puts your sign-in in front of every app.** OpenID Connect or GitHub, with
  roles and groups; each app says who can open it, and an app can ask who its
  viewer is.
- **Runs scheduled and background work.** Jobs on a schedule, jobs an app
  starts, reruns, and a status page for each.
- **Gives apps what they need, and nothing else.** Secrets, file storage, a
  database connection, Slack and email, all granted per app, with the network
  an app can reach stated rather than assumed.
- **Keeps a record.** Who deployed what and when, who opened which app, and
  what changed, in an audit log an assessor can read.
- **Runs on your machines.** One Go binary and Postgres, on one Linux machine
  with Docker Compose, or on Kubernetes with the Helm chart, each app isolated
  in its own account or pod.
- **Has a command-line client and app SDKs.** `toft` deploys, streams logs,
  rolls back, sets variables and moves files without a browser; the SDKs for
  Python, Node, Go and R give an app its storage, jobs, notifications and
  viewer.

## Changed

- **The Node SDK is `toft-sdk`.** Import `toft-sdk`; the old name,
  `@larchway/toft`, is still installed beside it through 0.10.x, and the build
  log says it is deprecated.
- **No image is published.** Build one with `docker build`, or run from source
  with `deploy/compose/compose.build.yml`; the Helm chart's `image.repository`
  has no default.
